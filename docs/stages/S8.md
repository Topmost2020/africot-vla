# Stage S8: Experiment tooling, Colab notebook, figures

## Purpose and place in the architecture

Stage S8 provides the tooling that turns controller runs into the tables and figures of the Results chapter, and the notebook that is intended to run the `africot_full` grid with the 7B model on a GPU, which the build environment lacks (`SPEC.md`). It is designed to keep the reporting rules of the integrity section mechanical: only reportable evaluation-seed runs enter the tables.

## What was built

The tooling was committed in `b3b412d` and the summary table and figures in `97d8623`.

- `run_grid.py`, which runs the product of controllers, scenarios and seeds, optionally in parallel, skips existing result files unless `--force` is given, and reports errors at the end without stopping the grid.
- `plots.py`, which writes `results/summary.csv`, `results/summary.md` and the figures in `figures/`.
- `colab_experiments.ipynb`, which mounts Google Drive, clones `claude/africot-build`, installs requirements while keeping the CUDA build of torch, sets cache and log directories on Drive, runs `run_grid.py` for `africot_full` with `--vlam-backend hf --vlam-model Qwen/Qwen2.5-VL-7B-Instruct --jobs 1`, prints per-run backend, calls, parse failures and latency, and copies the files into `results/` before rerunning `plots.py`.
- `tests/test_plots.py`.

## Exact settings

`plots.py` groups runs by scenario, controller, backend and model, and reports the mean and the sample standard deviation (`ddof=1`) over evaluation seeds 0 to 4. It drops any file with `vlam_backend` equal to `mock`, `reportable` false, or a `seed_role` other than `evaluation`, and does not read the `results/mock_wiring/` subdirectory. Metrics are average waiting time, average travel time, average queue length, throughput and pedestrian waiting time, with the insertion-delay definitions recorded in `DEVIATIONS.md`. Figures carry no baked-in figure numbers and use Times New Roman when installed, with a serif fallback (the font was absent in the build environment).

## How it was tested

The reviewer recorded 68 tests passing, including a test that a mock `africot_full` file and a tuning-seed file are excluded and that the mean uses the remaining runs. The reviewer regenerated the tables from the committed results and found `results/summary.csv` and `results/summary.md` byte-identical, covering 100 runs (fixed_time, count_timer, max_pressure, africot_nowm and africot_noslow across 4 scenarios and 5 seeds), with n equal to 5 in every group (`reviews/S8.md`). The table contains no `africot_full` row. Figures produced are `figures/awt_by_scenario.png`, `att_by_scenario.png`, `aql_by_scenario.png`, `throughput_by_scenario.png`, `ped_wait_by_scenario.png` and `world_model_training_curve.png`. Selected means from `results/summary.md` for the normal scenario are AWT 36.3 s, 38.1 s, 17.0 s, 39.9 s and 19.3 s for fixed_time, count_timer, max_pressure, africot_nowm and africot_noslow, with 0 safety violations in every group. The full table is given in `results/summary.md`.

The notebook was read cell by cell by the reviewer but has not been executed, because no GPU was available. Only its grid command was smoke-tested locally with the mock backend (`STATUS.md`, `reviews/S8.md`).

## Reviewer findings and resolution

The stage was approved without required fixes (`reviews/S8.md`). The notebook remains untested until its first Colab run, and any failure is to be recorded in `STATUS.md`. The error bars are sample standard deviations over 5 seeds, and captions must say so. The outage group duplicates market for every controller without a slow loop, so captions must explain that it is not an independent result. The legend position in `figures/awt_by_scenario.png` is close to the africot_nowm incident error bar, which is cosmetic.

## Limitations

No reportable `africot_full` result exists yet, so the central comparison of the dissertation is missing from the tables and must come from the Colab run. With n equal to 5, standard deviations are indicative only. Outage rows for controllers without a slow loop are copies of market rows by construction.

## Dissertation paragraph

Reporting is designed to be reproducible from committed files: a resumable grid runner writes one result file per controller, scenario and seed, and a plotting script is intended to build the tables and figures only from reportable runs on evaluation seeds, excluding mock-model and tuning runs by rule. The current summary covers five controllers in four scenarios with five seeds each (100 runs, `results/summary.md`) and does not yet include the full AfriCoT-VLA controller, whose 7B-model grid is prepared as a notebook for a GPU session and has not yet been executed.
